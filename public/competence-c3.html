Preuve 01 / 02 — SAE Linux, Binôme HOJA & SCHMITT

SAE Linux — Guide d'administration système

Réalisation en binôme d'un guide complet d'administration Linux : architecture système, installation de distributions, gestion des utilisateurs et des permissions, configuration réseau, processus, déploiement Apache/MariaDB.

Linux (Ubuntu/Debian/Fedora) Bash Apache MariaDB SSH

Contexte et ressources mobilisées

SAE Administration Linux en binôme — produire un guide couvrant l'utilisation et l'administration de Linux, depuis l'installation jusqu'à la configuration de services réseau. Distributions : Ubuntu LTS, Debian, Fedora. Environnements : GNOME, KDE, XFCE. Références : man pages, Arch Wiki, cours systèmes d'exploitation.

Activités et implication

  • Architecture système : modèle 3 couches (matériel → noyau → espace utilisateur), scheduler, mémoire virtuelle
  • CLI : navigation (ls, cd, find), manipulation fichiers, recherche grep/locate, éditeur vim/nano
  • Utilisateurs et permissions : adduser, usermod, userdel, groupadd, /etc/passwd, /etc/shadow, sudo, chmod/chown, ACL setfacl
  • Réseau : ip addr, ping, SSH (connexion + clés asymétriques), netstat/ss, /etc/hosts
  • Processus et services : ps/top/htop, kill/nice/cron — installation et configuration Apache (virtualhost) et MariaDB

Apprentissages clés

  • Passer du GUI au CLI : les commandes exposent l'état du système de façon directe et scriptable
  • Principe du moindre privilège : chaque processus tourne avec les droits minimaux (UID/GID, permissions)
  • SSH et clés asymétriques : première implémentation réelle d'authentification par clé publique/privée
  • Configuration fichiers vs. GUI : comprendre /etc/network/interfaces, resolv.conf plutôt que des menus graphiques

Preuve 02 / 02 — SAE S4 (volet infrastructure)

App Vote — Infrastructure Docker & Durcissement sécurité

Containerisation complète d'une application PHP/MariaDB avec Docker Compose et durcissement du serveur web : headers HTTP stricts (CSP), rate-limiting, session sécurisée. Score Mozilla Observatory amélioré de F à A.

Docker docker-compose CSP CSRF Rate-limiting

Contexte et ressources mobilisées

SAE S4 — 15 points d'infrastructure et sécurité à atteindre sur l'application héritée, chacun documenté avec implémentation vérifiable. Référentiels : OWASP Top 10, Mozilla Observatory, RFC 6797 (HSTS), MDN CSP Level 3.

Activités et implication

  • Docker Compose : Dockerfile (php:8.0-apache + extensions PDO), deux services séparés app/db, volumes pour persistance, variables d'environnement pour les secrets
  • Headers HTTP : CSP stricte (sources explicites), X-Frame-Options, HSTS, désactivation du directory listing Apache
  • Sécurité applicative : tokens CSRF sur tous les formulaires POST, rate-limiting PHP (5 tentatives/5 min par IP), reCAPTCHA v2, pages d'erreur sans stack trace
  • Session : session_set_cookie_params avec httponly=true, SameSite=Strict, secure=true

Apprentissages clés

  • Défense en profondeur : réseau → HTTP → applicatif → session — chaque couche réduit la surface d'attaque
  • Docker en contexte réel : réseaux bridge, volumes, secrets — au-delà des tutoriels
  • Mesure objective de la sécurité : Mozilla Observatory traduit des configurations techniques en score actionnable
